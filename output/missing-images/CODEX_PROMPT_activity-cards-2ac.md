# Prompt Codex : vignettes manquantes des activités 2AC

Tu travailles dans le dépôt InfoPlay Maroc (application web hors ligne, JS sans framework, build esbuild avec `npm run build`).

## Contexte

Sur une page de séance (`#/m/<module>/s/<séance>`), chaque carte d'activité affiche une vignette 112×112. Elle est choisie par `activityArt(a)` dans `src/app.js` (vers la ligne 668) :

1. la première image de `a.pics` ;
2. sinon la première clé de `STUDENT_ILLUSTRATIONS` qui commence par `(a.illus || a.id) + '-q'` ;
3. sinon `mechanicIcon(a.type)`, une simple icône SVG grise.

Les 120 activités du Tronc Commun ont toutes une vignette. En 2AC, **53 activités sur 92** tombent dans le cas 3 (exemple : « Les unités de mesure », `m21-s1-a4`, route `#/m/21/s/1/a/4`). Les images `label-illustrations` (lbl-xxxxxxxx) ne servent jamais de vignette : ne les réutilise pas pour ça.

La liste exacte est dans `output/missing-images/activity-cards-2ac.jsonl` : une ligne JSON par image, avec `id`, `src` (PNG source à produire), `file` (WebP publié), `module`, `session`, `activity`, `mech`, `route` et `visual` (la scène à dessiner, en anglais).

## Tâche

### 1. Générer les 53 images

Pour chaque ligne du fichier JSONL, génère une image carrée avec ton outil de génération d'images et enregistre-la dans `src` (`output/activity-cards-src/<id>.png`, au moins 1024×1024). Construis le prompt en mettant bout à bout le style commun et le champ `visual` de la ligne :

> Hand-drawn school-textbook illustration for a middle-school computing game, thick navy-blue outlines, flat pastel blue and teal fills, light flat shading, plain cream background (#fffaf0), one clear subject centred with generous margins, square format, readable at 112 px. Clearly a drawing: never photorealistic, never 3D. Absolutely no text, letters, digits, code or watermark: any screen, menu, cell or label is left blank or drawn as abstract lines. No brand logos (Microsoft, Excel, Windows, Google…). Moroccan context when natural, diverse characters, no stereotypes. Scene: `<visual>`

Règles :
- Ne montre jamais la réponse d'un exercice (aucune valeur, aucune bonne option mise en avant).
- Garde la même palette et le même trait que `public/images/student-illustrations/m1-s3-a2-q01-*.webp` : ouvre deux ou trois de ces images avant de commencer pour comparer.
- Si une image contient du texte lisible, un logo ou un rendu 3D, régénère-la.
- Le travail peut être repris : ne régénère pas un PNG qui existe déjà et qui est conforme.

### 2. Convertir en WebP 512×512

Crée `scripts/png-to-card-webp.mjs` sur le modèle de `scripts/png-to-label-webp.mjs` (même canvas 512×512 dans Playwright, fond `#fffaf0`, qualité 0.88). Il lit `output/activity-cards-src/*.png` (motif `^m\d+-s\d+-a\d+\.png$`) et écrit `public/images/activity-cards/<id>.webp`, en sautant les fichiers déjà convertis.

### 3. Index des vignettes

Crée `scripts/sync-activity-cards.mjs` sur le modèle de `scripts/sync-label-illustrations.mjs`. Il génère `src/data/activity-cards.js` :

```js
// Generated by scripts/sync-activity-cards.mjs from public/images/activity-cards/*.webp.
export const ACTIVITY_CARDS = {
  "m21-s1-a4": "images/activity-cards/m21-s1-a4.webp",
  …
};
```

Il affiche aussi le nombre de lignes du JSONL dont le fichier `file` manque encore.

### 4. Brancher dans l'application

Dans `src/app.js`, importe `ACTIVITY_CARDS` et modifie `activityArt(a)` : si aucune clé n'est trouvée par les règles 1 et 2, utilise `ACTIVITY_CARDS[a.id]` avant de revenir à `mechanicIcon(a.type)`. Garde la même balise `img` (classe `office-art tc-art`, 112×112, `loading="lazy"`, `onerror` qui remet l'icône). Ne change pas l'ordre des règles 1 et 2 : les vignettes existantes ne doivent pas bouger.

Ne touche ni aux illustrations des questions (`studentIllustration`, `data.pics`) ni aux `label-illustrations`. Les nouvelles images servent seulement de vignette de carte.

### 5. Test

Ajoute `tests/activity-cards.test.mjs` (`node:test`) qui vérifie :
- chaque activité du Tronc Commun (modules 1 à 4) et du 2AC (modules 21 à 25) obtient une vignette par la règle 1, 2 ou `ACTIVITY_CARDS` ;
- chaque chemin de `ACTIVITY_CARDS` existe dans `public/` ;
- chaque `id` de `ACTIVITY_CARDS` correspond à une activité existante.

### 6. Vérifier

```bash
node scripts/png-to-card-webp.mjs
node scripts/sync-activity-cards.mjs
npm run build
npm test
```

Ouvre ensuite l'application (`node scripts/lan-server.mjs`, port 8765, avec `?test=1`) et contrôle au moins ces séances : `#/m/21/s/1`, `#/m/22/s/2`, `#/m/24/s/8`, `#/m/25/s/4`. Chaque carte doit afficher une image et plus aucune icône grise. Fais une capture d'écran de `#/m/21/s/1`.
