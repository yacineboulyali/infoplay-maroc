# Prompt Codex : vignettes manquantes des activités 1AC et 3AC

Tu travailles dans le dépôt InfoPlay Maroc (application web hors ligne, JS sans framework, build esbuild avec `npm run build`).

## Contexte

Sur une page de séance (`#/m/<module>/s/<séance>`), chaque carte d'activité affiche une vignette 112×112. Elle est choisie par `activityArt(a)` dans `src/app.js` :

1. la première image de `a.pics` ;
2. sinon la première clé de `STUDENT_ILLUSTRATIONS` qui commence par `(a.illus || a.id) + '-q'` ;
3. sinon `mechanicIcon(a.type)`, une simple icône SVG grise.

Il manque des vignettes pour **19 activités 1AC sur 76** et **57 activités 3AC sur 96**, soit 76 images en tout. Le Tronc Commun est complet. Le 2AC a son propre prompt (`output/missing-images/CODEX_PROMPT_activity-cards-2ac.md`), qui a peut-être déjà été exécuté. Les images `label-illustrations` (lbl-xxxxxxxx) ne servent jamais de vignette : ne les réutilise pas pour ça.

Listes de travail, une ligne JSON par image :
- `output/missing-images/activity-cards-1ac.jsonl` (19 lignes)
- `output/missing-images/activity-cards-3ac.jsonl` (57 lignes)

Chaque ligne contient `id`, `src` (PNG source à produire), `file` (WebP publié), `level`, `module`, `session`, `activity`, `mech`, `route` et `visual` (la scène à dessiner, en anglais).

## Étape 0 : regarder ce qui existe déjà

Vérifie si le travail 2AC a déjà été intégré, c'est-à-dire si ces fichiers existent : `scripts/png-to-card-webp.mjs`, `scripts/sync-activity-cards.mjs`, `src/data/activity-cards.js`, `tests/activity-cards.test.mjs`, et si `activityArt` utilise déjà `ACTIVITY_CARDS`.
- **S'ils existent**, réutilise-les tels quels et passe directement à l'étape 1. Tu n'as qu'à étendre le test (étape 5).
- **Sinon**, crée-les comme décrit aux étapes 2 à 5.

## Tâche

### 1. Générer les 76 images

Pour chaque ligne des deux fichiers JSONL, génère une image carrée avec ton outil de génération d'images et enregistre-la dans `src` (`output/activity-cards-src/<id>.png`, au moins 1024×1024). Construis le prompt en mettant bout à bout le style commun et le champ `visual` de la ligne :

> Hand-drawn school-textbook illustration for a middle-school computing game, thick navy-blue outlines, flat pastel blue and teal fills, light flat shading, plain cream background (#fffaf0), one clear subject centred with generous margins, square format, readable at 112 px. Clearly a drawing: never photorealistic, never 3D. Absolutely no text, letters, digits, code, URLs, email addresses or watermark: any screen, menu, address bar, cell or label is left blank or drawn as abstract lines. No brand logos (Microsoft, PowerPoint, Gmail, Outlook, Chrome, Firefox, Google, Windows…). Moroccan context when natural, diverse characters, no stereotypes. Scene: `<visual>`

Règles :
- Ne montre jamais la réponse d'un exercice (aucune valeur, aucune bonne option mise en avant).
- Pour les thèmes Web et messagerie (3AC modules 4 et 5), les adresses, URL et mots de passe sont dessinés comme des blocs ou des symboles, jamais comme du texte lisible.
- Pour le Logo (3AC module 3), dessine la tortue et les tracés au crayon, jamais les instructions écrites.
- Garde la même palette et le même trait que `public/images/student-illustrations/m1-s3-a2-q01-*.webp`. Si des vignettes 2AC existent déjà dans `public/images/activity-cards/`, compare aussi avec elles pour garder l'ensemble cohérent.
- Si une image contient du texte lisible, un logo ou un rendu 3D, régénère-la.
- Le travail peut être repris : ne régénère pas un PNG qui existe déjà et qui est conforme.

### 2. Convertir en WebP 512×512 (si le script n'existe pas encore)

Crée `scripts/png-to-card-webp.mjs` sur le modèle de `scripts/png-to-label-webp.mjs` (même canvas 512×512 dans Playwright, fond `#fffaf0`, qualité 0.88). Il lit `output/activity-cards-src/*.png` (motif `^m\d+-s\d+-a\d+\.png$`) et écrit `public/images/activity-cards/<id>.webp`, en sautant les fichiers déjà convertis.

### 3. Index des vignettes (si le script n'existe pas encore)

Crée `scripts/sync-activity-cards.mjs` sur le modèle de `scripts/sync-label-illustrations.mjs`. Il génère `src/data/activity-cards.js` :

```js
// Generated by scripts/sync-activity-cards.mjs from public/images/activity-cards/*.webp.
export const ACTIVITY_CARDS = {
  "m11-s2-a4": "images/activity-cards/m11-s2-a4.webp",
  …
};
```

Il lit tous les fichiers `output/missing-images/activity-cards-*.jsonl` et affiche, par niveau, le nombre de lignes dont le fichier `file` manque encore.

### 4. Brancher dans l'application (si ce n'est pas déjà fait)

Dans `src/app.js`, importe `ACTIVITY_CARDS` et modifie `activityArt(a)` : si aucune clé n'est trouvée par les règles 1 et 2, utilise `ACTIVITY_CARDS[a.id]` avant de revenir à `mechanicIcon(a.type)`. Garde la même balise `img` (classe `office-art tc-art`, 112×112, `loading="lazy"`, `onerror` qui remet l'icône). Ne change pas l'ordre des règles 1 et 2 : les vignettes existantes ne doivent pas bouger.

Ne touche ni aux illustrations des questions (`studentIllustration`, `data.pics`) ni aux `label-illustrations`.

### 5. Test

Crée ou étends `tests/activity-cards.test.mjs` (`node:test`) pour qu'il vérifie :
- chaque activité du Tronc Commun (modules 1 à 4) et de **tous** les niveaux Collège (`COLLEGE_ACTIVITIES` : 1AC, 2AC, 3AC) obtient une vignette par la règle 1, 2 ou `ACTIVITY_CARDS` ;
- chaque chemin de `ACTIVITY_CARDS` existe dans `public/` ;
- chaque `id` de `ACTIVITY_CARDS` correspond à une activité existante.

Si le 2AC n'a pas encore ses images, limite temporairement la première vérification au Tronc Commun, au 1AC et au 3AC, et indique-le dans ton résumé.

### 6. Vérifier

```bash
node scripts/png-to-card-webp.mjs
node scripts/sync-activity-cards.mjs
npm run build
npm test
```

Ouvre ensuite l'application (`node scripts/lan-server.mjs`, port 8765, avec `?test=1`) et contrôle au moins ces séances : `#/m/14/s/3`, `#/m/15/s/1`, `#/m/15/s/3`, `#/m/32/s/2`, `#/m/33/s/3`, `#/m/34/s/4`, `#/m/35/s/5`. Chaque carte doit afficher une image et plus aucune icône grise. Fais une capture d'écran de `#/m/15/s/1` et de `#/m/34/s/4`.
