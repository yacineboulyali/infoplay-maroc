# Prompt Codex : icônes illustrées des modules (Collège, Lycée, OFPPT)

Tu travailles dans le dépôt InfoPlay Maroc (application web hors ligne, JS sans framework, build esbuild avec `npm run build`).

## Contexte

Chaque module (et chaque partie ou séance des parcours OFPPT) a un titre précédé d'une **emoji**. Elle s'affiche dans l'en-tête des cartes de module, `span.pp-ico` (environ 29 px, `src/styles/pro.css` : `.pro-part .pp-ico{font-size:1.8rem}`). Ces emoji sont génériques, et plusieurs modules partagent la même : 🖥️ pour TC M1, 1AC M1, 2AC M1 et EGTSI106 ; 🐢 pour 2AC M5 et 3AC M3 ; 🔎 pour 1AC M5 et 3AC M4 ; 🪟 pour 1AC M2, 2AC M2 et EGTSI S03. On les remplace par **28 icônes illustrées**, une par module, toutes différentes.

La liste est dans `output/missing-images/module-icons.jsonl`, une ligne par icône :
- `key` : clé de l'icône et nom du fichier ;
- `parcours`, `module` : où se trouve le module ;
- `emoji` : l'emoji actuelle, qui servira de repli ;
- `tile` : couleur du module ;
- `where` : écrans concernés ;
- `icon` : l'objet à dessiner, en anglais.

Répartition :
- Lycée · Tronc commun : 4 modules (`m1`…`m4`) ;
- Collège 1AC, 2AC, 3AC : 15 modules (`m11`…`m35`) ;
- OFPPT : `m205` (module M205) et ses 4 parties (`m205-word`, `m205-excel`, `m205-ppt`, `m205-outlook`), puis `egtsi106` (module EGTSI106) et ses 3 séances (`egtsi106-s1`…`s3`).

Emplacements actuels de l'emoji dans le code :

| Écran | Fichier | Code actuel |
|---|---|---|
| Tableau de bord Tronc commun `#/dash` | `src/app.js` (`dashScreen`) | `h('span', { class: 'pp-ico' }, m.icon)` |
| Parcours Collège `#/college/<n>` | `src/app.js` (écran niveau) | idem |
| Page d'un module `#/m/<id>` | `src/app.js` (`moduleScreen`) | `pp-ico` des groupes + `h1` `${m.icon} ${m.title}` |
| M205 `#/pro` | `src/pro/screens.js` | `h('span', { class: 'pp-ico' }, p.icon)` (parties `p.key` = word, excel, ppt, outlook) |
| EGTSI106 `#/egtsi106` | `src/egtsi106/screen.js` | `ICONS[i]` dans `pp-ico` |
| Accueil (cartes M205 et EGTSI106) | `src/app.js` (`homeScreen`) | `span.mode-ico` '💼' et '🖥️' |

## Tâche

### 1. Générer les 28 icônes

Pour chaque ligne, génère une image carrée et enregistre-la dans `output/module-icons-src/<key>.png` (au moins 1024×1024). Construis le prompt en mettant bout à bout le style commun et le champ `icon`, en remplaçant `<tile>` par la couleur de la ligne :

> Flat illustrated app-style icon for a school computing game. A rounded-square tile filled with a soft tint of <tile>, with a thin darker <tile> border, centred on a plain cream background (#fffaf0). Inside the tile, ONE bold, simple object drawn with thick navy-blue outlines and flat pastel fills (blue, teal, plus the tile colour as accent), light flat shading. Large shapes, very few details, perfectly readable at 40 px. Hand-drawn textbook style matching a cartoon illustration set, never photorealistic, never 3D, no gradients-heavy glossy effect. Absolutely no text, letters, digits or watermark. No brand logos (Microsoft, Word, Excel, PowerPoint, Outlook, Windows, Google…). Object: `<icon>`

Règles :
- **Lisibilité à 40 px** : vérifie chaque icône réduite à 40 px. Si on ne reconnaît plus l'objet, simplifie et régénère.
- **Toutes différentes** : compare les paires sensibles côte à côte et assure-toi qu'on les distingue au premier coup d'œil : `m25`/`m33`, `m15`/`m34`, `m1`/`m11`/`m21`/`egtsi106`, `m12`/`m22`/`egtsi106-s3`, `m4`/`m31`, `m205-outlook`/`m35`.
- **Cohérence de série** : même cadrage, même tuile, même épaisseur de trait, même place occupée pour les 28 icônes. Génère d'abord `m1`, `m24` et `m205-word`, fais une planche, ajuste le style, puis génère le reste.
- Pour M205, pas de logo ni de lettre W, X, P, O. Les couleurs bleu, vert, orange et teal suffisent à évoquer chaque logiciel.
- Si une icône contient du texte, un logo ou un rendu 3D, régénère-la.
- Le travail peut être repris : ne régénère pas un PNG existant et conforme.

### 2. Convertir en WebP

Crée `scripts/png-to-module-icon-webp.mjs` sur le modèle de `scripts/png-to-card-webp.mjs`. Il convertit `output/module-icons-src/<key>.png` en `public/images/module-icons/<key>.webp`, au format **256×256**, fond `#fffaf0`, qualité 0.9, en sautant les fichiers déjà convertis.

### 3. Index

Crée `scripts/sync-module-icons.mjs` sur le modèle de `scripts/sync-activity-cards.mjs`. Il génère `src/data/module-icons.js` :

```js
// Generated by scripts/sync-module-icons.mjs from public/images/module-icons/*.webp.
export const MODULE_ICONS = {
  "egtsi106": "images/module-icons/egtsi106.webp",
  "m1": "images/module-icons/m1.webp",
  …
};
```

Il affiche aussi les clés du JSONL dont le WebP manque encore.

### 4. Brancher dans l'application

Crée `src/utils/module-icon.js` :

```js
// Icône illustrée d'un module ; l'emoji reste en repli si l'image manque ou ne charge pas.
export function moduleIcon(key, emoji, className = 'pp-ico') { … }
```

Si `MODULE_ICONS[key]` existe, elle renvoie `<span class="<className> module-icon" aria-hidden="true"><img src=… alt="" width="48" height="48" loading="lazy" decoding="async" draggable="false"></span>`. Le `onerror` de l'image remplace le contenu par l'emoji. Sinon, elle renvoie le `span` actuel avec l'emoji.

Remplace l'emoji par `moduleIcon(...)` aux emplacements suivants :
- cartes de module du Tronc commun et du Collège : clé `'m' + m.id` ;
- groupes de la page module (`moduleScreen`) : clé `'m' + m.id` ;
- titre `h1` de la page module : icône 40 px placée avant le texte, sans emoji dans le texte ;
- parties M205 : clé `'m205-' + p.key` ;
- séances EGTSI106 : clé `'egtsi106-s' + (i + 1)` ;
- accueil : carte M205 avec `moduleIcon('m205', '💼', 'mode-ico')`, carte EGTSI106 avec `moduleIcon('egtsi106', '🖥️', 'mode-ico')` ;
- titres `h1` de `#/pro` et `#/egtsi106` : icône `m205` et `egtsi106` à la place de l'emoji.

Laisse l'emoji dans les textes courts où elle fait partie d'une phrase (fil d'Ariane, `act-kind` de la page activité, titre `h2` du bilan) : ne les modifie pas.

CSS, à mettre dans `src/styles/pro.css` ou la feuille qui définit `.pp-ico` :
- `.pp-ico.module-icon img` : 48×48 px, `border-radius:12px`, `display:block` ;
- `.mode-ico.module-icon img` : 56×56 px ;
- l'icône du `h1` : 40 px, alignée verticalement au centre du texte ;
- sous 480 px de large : 40 px pour `.pp-ico` ;
- garde `aria-hidden`, car le titre du module reste le nom accessible.

### 5. Test

Ajoute `tests/module-icons.test.mjs` (`node:test`) qui vérifie :
- chaque module de `CATALOG` (1 à 4) et de `COLLEGE_MODULES` a une entrée `MODULE_ICONS['m' + id]` ;
- les clés `m205`, `m205-word`, `m205-excel`, `m205-ppt`, `m205-outlook`, `egtsi106`, `egtsi106-s1`, `egtsi106-s2`, `egtsi106-s3` existent ;
- chaque chemin existe dans `public/` ;
- toutes les clés du JSONL sont indexées, et aucune clé indexée n'est inconnue.

### 6. Vérifier

```bash
node scripts/png-to-module-icon-webp.mjs
node scripts/sync-module-icons.mjs
npm run build
npm test
```

Ouvre l'application (`node scripts/lan-server.mjs`, port 8765, `?test=1`) et contrôle : l'accueil, `#/dash`, `#/college/1`, `#/college/2`, `#/college/3`, `#/m/24`, `#/pro`, `#/egtsi106`, en largeur bureau puis mobile (375 px). Aucune emoji ne doit rester dans les en-têtes de cartes de module, et aucune icône ne doit être déformée ni déborder. Fais une capture de `#/college/2`, `#/pro` et `#/egtsi106`, plus une planche des 28 icônes côte à côte à 48 px, que tu enregistres dans `output/module-icons-review.png`.
